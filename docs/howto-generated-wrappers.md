# How to switch from ReflectWrapper to generated wrappers

This guide replaces a `function.MustReflectWrapper` call with a wrapper generated by `gen-func-wrappers`. Afterwards the argument names come from your source code, argument descriptions from the doc comment show up in CLI help and as form labels, and CI catches wrappers that no longer match their function.

The examples use the `tempconv` program from the [tutorial](tutorial-one-function-four-ways.md). The steps are the same for any package-level function.

## Prerequisites

- go-function v1.0.0 or later, Go 1.26 or later
- A package-level function wrapped with `ReflectWrapper` or `MustReflectWrapper`, like:

  ```go
  // Convert converts a temperature to the unit "C" (Celsius) or "F" (Fahrenheit).
  func Convert(ctx context.Context, degrees float64, to string) (float64, error) {
  	// ...
  }

  var convert = function.MustReflectWrapper(Convert, "ctx", "degrees", "to")
  ```

Closures and method values like `svc.Get` can't be generated. Keep `ReflectWrapper` for those.

## Steps

1. Add the generator as a tool of your module:

   ```bash
   go get -tool github.com/domonda/go-function/cmd/gen-func-wrappers@latest
   ```

   This adds a `tool` directive to `go.mod`, so `go tool gen-func-wrappers` runs the version your module pins.

2. Describe the arguments in the doc comment of the function, one `argName: description` line each. A list under `Arguments:` is the common form:

   ```go
   // Convert converts a temperature to another unit.
   //
   // Arguments:
   //   - degrees: The temperature to convert
   //   - to: The unit to convert to, C (Celsius) or F (Fahrenheit)
   func Convert(ctx context.Context, degrees float64, to string) (float64, error) {
   ```

   The description is the rest of the line. Arguments without a line get an empty description.

3. Replace the `MustReflectWrapper` call with `function.WrapperTODO`, keeping the variable name:

   ```go
   var convert = function.WrapperTODO(Convert)
   ```

   The argument names are gone: the generator reads them from `Convert`.

4. Add a `go:generate` directive to the file, below the `package` clause:

   ```go
   package main

   //go:generate go tool gen-func-wrappers $GOFILE
   ```

5. Run the generator:

   ```bash
   go generate ./...
   ```

   It prints nothing on success, and replaces the `WrapperTODO` line with a type and its methods:

   ```go
   // convert wraps Convert as function.Wrapper (generated code)
   var convert convertT

   // convertT wraps Convert as function.Wrapper (generated code)
   type convertT struct{}

   func (convertT) String() string {
   	return "main.Convert(ctx context.Context, degrees float64, to string) (float64, error)"
   }

   func (convertT) ArgNames() []string {
   	return []string{"ctx", "degrees", "to"}
   }

   func (convertT) ArgDescriptions() []string {
   	return []string{"", "The temperature to convert", "The unit to convert to, C (Celsius) or F (Fahrenheit)"}
   }

   // ... Call, CallWithStrings, CallWithNamedStrings, CallWithJSON
   ```

   It also adds the imports the generated code needs. The variable now has the type `convertT`, which implements `function.Wrapper`, so code that passes `convert` to `cli`, `httpfun`, or `htmlform` compiles unchanged.

6. Check generated wrappers in CI. `-validate` changes no files and exits with code 1 if a wrapper is missing or outdated, and with code 2 for other errors like a file that doesn't parse. In a GitHub Actions workflow:

   ```yaml
   - name: Check generated wrappers are up to date
     run: go tool gen-func-wrappers -validate ./...
   ```

## Verification

Build and run the program. The CLI help now lists the argument descriptions:

```bash
go build -o tempconv . && ./tempconv
```

```
Commands:
  tempconv
      Print the commands

  tempconv convert <degrees:float64> <to:string>
      Convert a temperature to C or F
          <degrees:float64> The temperature to convert
          <to:string> The unit to convert to, C (Celsius) or F (Fahrenheit)

  tempconv serve <addr:string>
      Serve the converter over HTTP
```

The form at `/form` labels its fields `The temperature to convert:` and `The unit to convert to, C (Celsius) or F (Fahrenheit):` instead of `degrees:` and `to:`.

`go tool gen-func-wrappers -validate ./...` exits with code 0 and prints nothing.

## Keeping wrappers current

Run `go generate ./...` again after you change a wrapped function:

| Change | Without regenerating |
|---|---|
| argument types, number of arguments or results | the generated code doesn't compile |
| result types | it compiles, but `String` and `ResultTypes` report the old types, `-validate` fails |
| argument names or descriptions | old names and descriptions stay, `-validate` fails |
| function body | nothing to do |

Upgrading go-function to a version whose generated code changed also makes `-validate` fail. The [CHANGELOG](../CHANGELOG.md) says when that happens.

## Troubleshooting

**The program panics at start with `function.WrapperTODO: run gen-func-wrappers`.**
`go generate` didn't run for this file, or the file has no `go:generate` directive and `go generate ./...` skipped it. Run `go tool gen-func-wrappers path/to/file.go` directly.

**`gen-func-wrappers error: /path/to/main.go: function wrappers are missing or outdated` from `-validate`.**
A `WrapperTODO` is left, or a function changed since its wrapper was generated. Run `go generate ./...` and commit the result.

**`can't find function func(a int) int { return a } in package`.**
The generator only wraps functions declared at package level. Name the function, or keep `ReflectWrapper` for the closure.

**`can't find package svc of svc.Get in the imports of the file`.**
Method values aren't supported. Write a package-level function that calls the method, or keep `ReflectWrapper`.

**Arguments are named `arg0`, `arg1` in help text and forms.**
The function declaration has unnamed parameters like `func Add(int, int) int`. Name them.

**More errors**, like import alias conflicts and dot imports, are covered in the [gen-func-wrappers README](../cmd/gen-func-wrappers/README.md#troubleshooting).
