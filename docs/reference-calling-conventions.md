# Calling conventions reference

Every [`function.Wrapper`](https://pkg.go.dev/github.com/domonda/go-function#Wrapper) can call its function in four ways: with typed values, positional strings, named strings, or a JSON object. This page lists how each convention maps its input to the arguments of the function, what it returns, and which errors it produces.

`ReflectWrapper`, wrappers generated by [`gen-func-wrappers`](../cmd/gen-func-wrappers/README.md), `VoidFuncWrapper`, and `ErrorFuncWrapper` behave the same unless a row or note says otherwise. Full signatures and doc comments are on [pkg.go.dev](https://pkg.go.dev/github.com/domonda/go-function).

## Methods

```go
type Wrapper interface {
	Description
	Call(ctx context.Context, args []any) (results []any, err error)
	CallWithStrings(ctx context.Context, args ...string) (results []any, err error)
	CallWithNamedStrings(ctx context.Context, args map[string]string) (results []any, err error)
	CallWithJSON(ctx context.Context, argsJSON []byte) (results []any, err error)
}
```

Each method is also its own interface (`CallWrapper`, `CallWithStringsWrapper`, `CallWithNamedStringsWrapper`, `CallWithJSONWrapper`), so code can depend on just the convention it uses. `httpfun.Handler`, for example, takes a `CallWithNamedStringsWrapper`.

## Arguments

| | `Call` | `CallWithStrings` | `CallWithNamedStrings` | `CallWithJSON` |
|---|---|---|---|---|
| Input matched by | position | position | argument name | JSON object key |
| First argument of type `context.Context` | gets `ctx`, not part of `args` | gets `ctx` | gets `ctx` | gets `ctx` |
| Missing argument | zero value | zero value | zero value | zero value |
| More input than arguments | error | error, except for a variadic function | names that aren't arguments are ignored | keys that aren't arguments are ignored |
| Conversion | none, the value must be [assignable](https://go.dev/ref/spec#Assignability) to the argument type | [`ScanString`](reference-string-conversion.md) | [`ScanString`](reference-string-conversion.md) | `json.Unmarshal` |
| Untyped `nil` or JSON `null` | zero value | | | zero value |
| Argument of type `any` | the value as passed | the string, not parsed | the string, not parsed | what `json.Unmarshal` produces, like `float64(42)` for `42` |
| Argument of type `error` | the value as passed | `nil` for `""`, `nil`, `null`, else `errors.New` of the trimmed string | like `CallWithStrings` | a JSON string with the message, `nil` for `""` or `null` |
| Variadic last argument `xs ...T` | one `[]T` value | every string from its position on is one element | one string, parsed as a slice literal like `[1,2]` | a JSON array |
| Name comparison | | | exact, case-sensitive | exact, case-sensitive |
| Whole input | | | a nil map passes no arguments | must be a JSON object or `null`, which counts as `{}` |

Assignability in `Call` follows the Go spec: a `[]int` is accepted for an argument of type `MyInts` with underlying type `[]int`, but an `int` is rejected for `MyInt`, and an `int64` for `int`.

Generated wrappers assign the string to an argument of type `string` directly, while `ReflectWrapper` passes it through `ScanString`. The result is the same unless a scanner is registered for `string` or for kind `reflect.String`, which then only applies to `ReflectWrapper`.

Strings for arguments of kind `string` are passed unchanged by the default scanner, including surrounding whitespace. Most other types trim whitespace before parsing, see [String conversion reference](reference-string-conversion.md).

## Results

- `results` holds every result of the function except a last result of type `error`, which is returned as `err`.
- If converting an argument fails, the function is not called and `results` is nil.
- Panics of the function are not recovered by the `Call*` methods. `httpfun.Handler` recovers them if `httpfun.CatchHandlerPanics` is true (the default), and `htmlform.Handler` always does. The `cli` dispatchers don't.

## Errors

| Error | Returned by | When |
|---|---|---|
| [`ErrParseArgString`](https://pkg.go.dev/github.com/domonda/go-function#ErrParseArgString) `{Err, Func, ArgName, ArgValue}` | `CallWithStrings`, `CallWithNamedStrings` | `ScanString` fails for an argument |
| [`ErrParseArgJSON`](https://pkg.go.dev/github.com/domonda/go-function#ErrParseArgJSON) `{Err, Func, ArgName}` | `CallWithJSON` | `json.Unmarshal` fails for the value of an argument |
| [`ErrParseArgsJSON`](https://pkg.go.dev/github.com/domonda/go-function#ErrParseArgsJSON) `{Err, Func}` | `CallWithJSON` | the input is not a JSON object or `null`, like an array |
| `N arguments passed, but function F takes M` | `Call`, `CallWithStrings` | more input than arguments |
| `can't use T as type U for argument 'a' of function F` | `Call` | a value isn't assignable to its argument type |

The three parse error types are struct values, not pointers. Match them with `errors.AsType[function.ErrParseArgString](err)` or `errors.As`. All three unwrap to the error of the scanner or JSON decoder. They don't add the argument value or the JSON input to their `Error()` text, because those can be large or private. The wrapped scanner error usually quotes the value, though, like `can't parse "hot" as float because of: invalid syntax`, so treat the text like request data when you log it. `ErrParseArgString.ArgValue` holds the complete value.

`Func` is the wrapper that failed. `httpfun.Handler` uses it to tell an invalid request argument (400) from a parse error inside the function (500), see [HTTP status codes](reference-http-status-codes.md).

## Examples

All four conventions calling the same variadic function:

```go
w := function.MustReflectWrapper(func(prefix string, xs ...int) string {
	return fmt.Sprint(prefix, xs)
}, "prefix", "xs")

w.Call(ctx, []any{"p", []int{1, 2}})                                         // [p[1 2]]
w.CallWithStrings(ctx, "p", "1", "2")                                        // [p[1 2]]
w.CallWithNamedStrings(ctx, map[string]string{"prefix": "p", "xs": "[1,2]"}) // [p[1 2]]
w.CallWithJSON(ctx, []byte(`{"prefix":"p","xs":[1,2]}`))                     // [p[1 2]]

w.CallWithStrings(ctx, "p")          // [p[]]
w.CallWithStrings(ctx, "p", "[1,2]") // error: can't parse "[1,2]" as int
```

Arguments of type `any`:

```go
w := function.MustReflectWrapper(func(x any) string { return fmt.Sprintf("%T", x) }, "x")

w.Call(ctx, []any{42})                                    // [int]
w.CallWithStrings(ctx, "42")                              // [string]
w.CallWithNamedStrings(ctx, map[string]string{"x": "42"}) // [string]
w.CallWithJSON(ctx, []byte(`{"x":42}`))                   // [float64]
```

Missing, extra, and misnamed input:

```go
w := function.MustReflectWrapper(func(a int, b string) string {
	return fmt.Sprintf("a=%d b=%q", a, b)
}, "a", "b")

w.Call(ctx, []any{1})                                    // [a=1 b=""]
w.Call(ctx, []any{nil, nil})                             // [a=0 b=""]
w.Call(ctx, []any{int64(1)})                             // error: can't use int64 as type int
w.CallWithStrings(ctx, "1", "x", "extra")                // error: 3 arguments passed, but ... takes 2
w.CallWithNamedStrings(ctx, map[string]string{"A": "1"}) // [a=0 b=""], names are case-sensitive
w.CallWithJSON(ctx, []byte(`{"a":1,"b":"x","c":1}`))     // [a=1 b="x"], c is ignored
w.CallWithJSON(ctx, []byte(`{"a":"1"}`))                 // ErrParseArgJSON for "a"
w.CallWithJSON(ctx, []byte(`[1,"x"]`))                   // ErrParseArgsJSON
```

## ReflectWrapper argument names

```go
func ReflectWrapper(function any, argNames ...string) (Wrapper, error)
func MustReflectWrapper(function any, argNames ...string) Wrapper
```

Pass one name per argument, including the `context.Context` argument. A different number of names is an error like `1 argNames passed, but func(int, int) has 2 arguments`. A function whose only argument is a `context.Context` can be wrapped without names, it gets the name `ctx`.

The names are used by `CallWithNamedStrings`, `CallWithJSON`, `httpfun` request parameters, `htmlform` field names, and `cli` help text. Generated wrappers take the names from the source code instead. [Architecture](explanation-architecture.md#why-reflectwrapper-needs-argument-names) explains why reflection can't.

## Description

| Method | `ReflectWrapper` | Generated wrapper | `ReflectDescription(name, f)` |
|---|---|---|---|
| `Name()` | `pkg.Func`, the package name guessed from the import path like goimports does | `pkg.Func` with the package name of the source file | `name` unchanged |
| `String()` | signature like `pkg.Func(a int, b string) (int, error)` | same format | same format with `name` |
| `ArgNames()` | the passed names | the parameter names, `arg0`, `arg1`, ... for unnamed ones | `a0`, `a1`, ... |
| `ArgDescriptions()` | empty strings | from `argName: description` lines of the doc comment | empty strings |
| `ArgTypes()` | argument types, a variadic argument as its slice type | same | same |
| `Variadic()` | true for `func(xs ...T)`, false for `func(xs []T)` | same | same |
| `NumArgs()`, `ContextArg()` | count includes the context argument | same | same |
| `NumResults()`, `ResultTypes()`, `ErrorResult()` | include a last `error` result | same | same |

`VoidFuncWrapper` and `ErrorFuncWrapper` return their signature, `func()` or `func() error`, as `Name` and `String`. The slices returned by `ArgNames`, `ArgDescriptions`, `ArgTypes`, and `ResultTypes` are copies the caller may modify.

## Adapters

| Type | Wraps |
|---|---|
| `VoidFuncWrapper` | a `func()` as complete `Wrapper` |
| `ErrorFuncWrapper` | a `func() error` as complete `Wrapper` |
| `CallWrapperFunc`, `CallWithStringsWrapperFunc`, `CallWithNamedStringsWrapperFunc`, `CallWithJSONWrapperFunc` | a function with the signature of one call method as that interface |
| `NewStringArgsFunc`, `NewNamedStringArgsFunc`, `NewJSONArgsFunc` | a call interface plus results handlers as one `func(ctx, input) error` |

`VoidFuncWrapper` and `ErrorFuncWrapper` return an error for passed arguments, strings, or JSON that is not an object, and ignore named strings and the values of a JSON object.

## Results handlers

A [`ResultsHandler`](https://pkg.go.dev/github.com/domonda/go-function#ResultsHandler) gets the results of a call after it returns. The `cli` dispatchers and `NewStringArgsFunc` and its siblings pass results to the handlers in order.

```go
type ResultsHandler interface {
	HandleResults(ctx context.Context, results []any, resultErr error) error
}
```

- A handler with nothing to do for a non-nil `resultErr` returns `resultErr`.
- A handler that fails, like when writing fails, returns its own error. That error is returned instead of `resultErr`, and later handlers are not called.
- Returning `nil` does not swallow `resultErr`: it is still returned after all handlers ran.

| Handler | Output |
|---|---|
| `Println` | `fmt.Println` per result |
| `PrintlnTo(w io.Writer)` | `fmt.Fprintln(w, result)` per result |
| `PrintTo(w io.Writer)` | one `fmt.Fprint(w, results...)` |
| `PrintlnWithPrefix(prefix)`, `PrintlnWithPrefixTo(prefix, w)` | `prefix result` per line |
| `LogTo(logger)`, `LogWithPrefixTo(prefix, logger)` | one `logger.Printf` line, `*log.Logger` implements `Logger` |
| `PrintlnText("text")` | prints the fixed text if there was no error |
| `PrintStructSliceAsTable` | slices of structs or struct pointers as a padded table on `os.Stdout`, exported fields as columns |

All handlers except `PrintlnText` and `PrintStructSliceAsTable` format results like this, in this order:

| Result | Printed as |
|---|---|
| implements `fmt.GoStringer` | `GoString()` |
| implements `fmt.Stringer` | `String()` |
| `[]string` | elements joined with newlines |
| `[]byte` | text if it's valid UTF-8 without control characters (except whitespace), else hex like `0x00ff` |
| `[][]string` | padded table with `\|` between columns |
| float, also behind pointers | up to 12 decimals, no trailing zeros: `3.14`, `212` |
| struct, map, slice, array, also behind pointers | indented JSON |
| func, chan | Go syntax via `%#v` |
| everything else | default `fmt` formatting |
