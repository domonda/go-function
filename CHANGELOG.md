# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

The root module and the `cli` and `cmd/gen-func-wrappers` submodules
are released together with the same version. Until v0.7.1 the `htmlform` submodule
was released with them, it moved to `github.com/domonda/go-htmlform`.

## [1.0.0] - 2026-10-20

First stable release: the APIs of all modules and the code generated
by `gen-func-wrappers` are now covered by semantic versioning.

### Added

- `httpfun.DefaultHandleError` is the default `HandleError`,
  so custom error handlers can delegate to it and keep its status codes.
- `Description.Variadic` reports if the last argument is variadic like `...int`,
  which `ArgTypes` can't show because it returns the slice type for both `...int` and `[]int`.
  The cli help shows a variadic argument like `<nums:...int>`.
- `httpfun.ErrorHandler` and `httpfun.ErrorHandlerFunc` are the error handlers
  of `httpfun.Handler`, `HandlerNoWrapper` and `HandleError`.
  The handlers of `httperr` like `httperr.DefaultHandler` implement `ErrorHandler`.
- `MaxSliceLiteralElements` (default 1 << 20, a value <= 0 disables it) limits the elements
  of every slice and array literal scanned from a string, except for `[]any` destinations
  and arrays in JSON objects, which `encoding/json` decodes.
- `httpfun.MaxRequestBodySize` (default 32 MiB, a value <= 0 disables it) limits the request bodies
  read by `RequestBodyAsArg` and `RequestBodyJSONFieldsAsArgs`.

### Changed

- **Breaking:** the `htmlform` module moved to its own repository as `github.com/domonda/go-htmlform`,
  so the modules of this repository no longer depend on go-fs.
  Its last release from this repository is `htmlform/v0.7.1`; change the import path
  `github.com/domonda/go-function/htmlform` to `github.com/domonda/go-htmlform`.
- **Breaking:** all modules require Go 1.26 instead of Go 1.25.
- **Breaking:** `ReflectWrapper`'s `NumResults` and `ResultTypes` include a trailing error result,
  like the `Description` documentation, `ReflectDescription` and generated wrappers.
- **Breaking:** the code generator package moved to `cmd/gen-func-wrappers/internal/gen`
  and can no longer be imported.
- **Breaking:** code generated by `gen-func-wrappers` changed, so `-validate` reports wrappers
  generated by earlier versions as outdated: regenerate them with `go generate` after upgrading.
  Wrappers generated by earlier versions don't compile with v1.0.0,
  and code generated by v1.0.0 needs go-function v1.0.0: upgrade both modules together.
- **Breaking:** `Description` has the method `Variadic`,
  which other implementations of `Description` and `Wrapper` have to add.
- **Breaking:** `httpfun.Handler` and `HandlerNoWrapper` take `httpfun.ErrorHandler` error handlers
  instead of `httperr.Handler`, so the API of httpfun has no types of go-httpx.
  The error handlers are tried in order until one returns true because it handled the error,
  instead of calling all of them, and `HandleError` answers errors that none of them handled
  instead of responding with an empty 200 OK, so an error handler that writes a response must return true.
- **Breaking:** `httpfun.HandleError` is an `httpfun.ErrorHandlerFunc` and `DefaultHandleError`
  returns if it handled the error, so custom `HandleError` functions return a bool.
- **Breaking:** `httpfun.RequestQueryArgs` and `RequestMultipartFormArgs` pass multiple values
  of a param as slice literal of JSON strings like `["1","2"]` instead of joining them with `;`,
  so they are the elements of slice and array arguments of types scanned from strings like numbers.
- **Breaking:** `httpfun.RequestBodyJSONFieldsAsArgs` leaves out fields with the value `null`
  like missing fields, so a string argument gets `""` instead of `"null"`,
  and with `MergeRequestArgs` a null field no longer replaces the argument of an earlier source.
- **Breaking:** `httpfun.RespondContentType` returns a `ResultsWriterFunc` like `RespondBinary`.
- **Breaking:** `httpfun.RequestQueryArg` and `RequestQueryAsArg` leave out a query param
  that is not in the request instead of passing an empty string, so they no longer overwrite
  defaults of earlier getters of `MergeRequestArgs` like `ConstRequestArg` with zero values,
  and pass multiple values like `RequestQueryArgs` instead of only the first one.
  The header getters keep setting missing headers to an empty string,
  so a trusted header placed last overwrites client values also if it is missing.
- **Breaking:** `ReflectWrapper` returns an error for a nil value of a function type,
  which panicked when called, and for empty or duplicate argument names except `_`,
  which can't be passed by name or got the same value by name.
  Like generated wrappers, its `CallWithStrings`, `CallWithNamedStrings` and `CallWithJSON`
  pass the zero value for arguments named `_` instead of the string or JSON value
  passed for them, so a client can't set them with the name or key `_`.
- **Breaking:** `httpfun.Handler` passes other errors of a `RequestArgsFunc` to its error handlers
  wrapped as errors of the request, which `httperr.DefaultHandler` and `DefaultHandleError`
  answer with 400 Bad Request, instead of unwrapped, which they answered with 500 Internal Server Error
  or 404 Not Found for `os.ErrNotExist` and `sql.ErrNoRows`. A custom `RequestArgsFunc`
  that fails because of the server, like a session lookup with a database error,
  returns an error carrying its response, like `httperr.New(http.StatusServiceUnavailable)`.
- **Breaking:** `httpfun.RespondRedirect` and `RespondRedirectFunc` redirect requests with other methods
  than GET and HEAD after the function call with 303 See Other instead of 302 Found,
  because browsers repeat PUT, PATCH and DELETE requests at the URL of a 302 redirect.
  Form POSTs and Go clients already followed a 302 with GET, so they behave the same.
  As `http.Handler` both keep redirecting with 302.
- **Breaking:** cli command names with a non-graphic character like a terminal escape sequence
  are rejected, instead of only names without any graphic character.
- **Breaking:** the loggers of a `cli.SuperStringArgsDispatcher` get the super command and the command
  joined with a space like `user create`, and the super command like `deploy` for its default command,
  instead of only the command of the super command.
- **Breaking:** `DispatchDefaultCommand` of `cli.StringArgsDispatcher` and `SuperStringArgsDispatcher`
  takes a `context.Context` instead of using `context.Background()`.
- **Breaking:** removed `MustDispatch`, `MustDispatchDefaultCommand` and `MustDispatchCombinedCommandAndArgs`
  of both cli dispatchers, which panicked for user input like an unknown command:
  use the `Dispatch` methods and handle their errors.
- **Breaking:** the fields of `TypeStringScanners` are unexported, so a `TypeStringScanners`
  is only changed by its `With` methods, which return a copy.
  `WithTypeScanner`, `WithInterfaceTypeScanner` and `WithKindScanner` panic for a nil scanner or type,
  and `WithInterfaceTypeScanner` for a type that is no interface,
  instead of making every later scan of a matching destination panic.
- **Breaking:** the field `Arg` of `ErrParseArgJSON` is named `ArgName` like in `ErrParseArgString`,
  `ErrParseArgsJSON` no longer has the field `JSON` with a copy of the arguments,
  and `NewErrParseArgsJSON` no longer takes them, because they can be large or private.
  For the same reason the message of `ErrParseArgString` no longer contains the argument value,
  and errors of `ScanString` for numbers and `time.Duration` quote the string once instead of twice:
  errors for numbers wrap the reason like `strconv.ErrSyntax` instead of the `*strconv.NumError`.
- **Breaking:** removed `CallFunctionWithJSONArgs`, a reflection based copy of `CallWithJSON`:
  `NewJSONArgsFunc` takes a `CallWithJSONWrapper` and calls its `CallWithJSON` method.
- **Breaking:** `ScanStrings` returns an error for different numbers of strings and destinations
  instead of only scanning as many as both have.
- **Breaking:** `VoidFuncWrapper` and `ErrorFuncWrapper` return an error for passed arguments or strings
  and for JSON that is no object like `ReflectWrapper`, instead of calling the function.
- **Breaking:** `CallWithStrings` of `ReflectWrapper` and generated wrappers returns an error
  for more strings than arguments instead of ignoring them, and every string from the position
  of a variadic argument on is one of its elements, also a single string, like in a Go call;
  a single string is no longer parsed as a slice literal (`CallWithNamedStrings` still parses `"[1,2]"`).
- **Breaking:** generated `CallWithJSON` methods match JSON keys to the exact argument names
  like `ReflectWrapper`: keys differing only in case are ignored, an invalid argument value
  returns an `ErrParseArgJSON` naming the argument, `error` arguments are unmarshalled from
  their message string, and missing arguments are zero values.
- **Breaking:** `ReflectWrapper.CallWithJSON` returns an `ErrParseArgJSON` naming the argument
  for an invalid argument value instead of an `ErrParseArgsJSON`, like generated wrappers.
- **Breaking:** `Name` and `String` of `ReflectWrapper` and generated wrappers
  use one format: `Name` returns the name qualified with the package like `strings.ToUpper`,
  and `String` the signature like `strings.ToUpper(s string) string`
  with one argument per name and the results without names.
  `String` of `ReflectDescription` uses the same format with the passed name.
  Generated wrappers qualify the name with the package name of the source file.
  `ReflectWrapper` only knows the import path, so it uses the package name
  that goimports assumes for it, like `function.ScanString` for `github.com/domonda/go-function`
  and `yaml.Marshal` for `gopkg.in/yaml.v3`.
  Both write empty interfaces as `any` in `String`, also where reflect writes `interface {}`
  or the source code `interface{}`, like in `map[string]any`.
- **Breaking:** wrapping a function of a package imported with a name of the generated code,
  like `v`, `ok`, `raw`, `i` or `str`, is an error asking to import it with another name.
- **Breaking:** `httpfun.RequestBodyAsArg` and `RequestBodyJSONFieldsAsArgs` reject request bodies
  over `httpfun.MaxRequestBodySize`, answered with 413 Request Entity Too Large.
- **Breaking:** elements of slice and array literals that are JSON strings are unquoted,
  so `["a","b"]` scans as `a` and `b` instead of keeping the quotes.
  Quoted elements are explicit strings: `""` and `"null"` are not zero values,
  so `[1, "", 3]` as `[]int` is an error and `["", "null"]` as `[]*string`
  gives pointers to `""` and `"null"`; elements scanned as JSON, like `json.RawMessage` or `any`,
  get a quoted element as JSON string.
- **Breaking:** malformed slice literals like `[1][2]`, `[,]` or `[1,]` are rejected,
  and `[ ]` scans as an empty slice.
- `httpfun.Handler` answers an argument value the function can't parse
  with 400 Bad Request instead of 500 Internal Server Error,
  and a request body over the size limit, or multipart form fields over the memory
  that `http.Request.ParseMultipartForm` allows for them, with 413 Request Entity Too Large.
  The response names the argument but not its value or the parse error,
  and the `ResultsWriter` is not called, which got the parse error as result error before.
  Errors from parsing arguments of other functions that the wrapped function called,
  file system errors of a `RequestArgsFunc` like a failed temporary file of an upload,
  and a missing environment variable of `RequestArgFromEnvVar`, are errors of the server.
  Errors of a `RequestArgsFunc` that carry their own response, like `httperr.Unauthorized`,
  get it instead of 400 Bad Request, also if they are joined with other errors,
  and without error handlers `httpfun.Handler` passes errors of reading the request
  to `HandleError` instead of answering them with 400 Bad Request.
- Generated `Call` methods return an error for too many arguments or an argument
  that is not assignable to its type, accept assignable values like a `[]int` for `type MyInts []int`,
  and pass missing or untyped nil arguments as zero values, like `ReflectWrapper`.
- Scanners registered in `StringScanners` also apply to elements of slices and arrays
  and to pointer targets, so `CallWithStrings` and `CallWithNamedStrings`
  scan them like top-level arguments.
- When several interface scanners registered with `WithInterfaceTypeScanner` match,
  the choice is deterministic: interfaces implemented by the type itself come before
  those only implemented by its pointer type, each sorted by type name.
- `gen-func-wrappers -validate` exits with 1 only if wrappers are missing or outdated
  and with 2 for all other errors, and reports every file with missing or outdated wrappers
  instead of stopping at the first one.
- Generated `CallWithStrings` and `CallWithNamedStrings` methods pass the unparsed string
  to arguments of type `any`, and scan `string` arguments and variadic `...string` elements
  with `ScanString` instead of assigning them, like `ReflectWrapper`,
  so that scanners registered for `string` or kind `reflect.String` apply to both.
- `gen-func-wrappers` selects the files of a package like the go command.
  Files with build constraints that need custom build tags, like `//go:build integration`,
  and files with names starting with `_` or `.` are skipped in directory mode,
  and naming such a file is an error.
  Files of a `main` package are rewritten instead of failing with "package not found".
- `gen-func-wrappers` processes every path argument, skips `vendor`, `testdata`,
  `_`-prefixed directories and nested modules in recursive mode like the go command,
  and `-replaceForJSON` can be repeated.
- `gen-func-wrappers` removes imports that a rewritten file no longer uses.
  When it adds no import, the file is formatted like gofmt and its import groups are kept.
- `cmd/gen-func-wrappers` uses `github.com/ungerik/go-astvisit`
  `v0.0.0-20261013080339-68c5a526b805` and its new import API.
- Dependencies updated, among them `testify` v1.11.1 → v1.12.1,
  `golang.org/x/tools` v0.48.0 → v0.52.0 and `golang.org/x/mod` v0.38.0 → v0.42.0.

### Fixed

- `ReflectWrapper` calls variadic functions from all `Call*` methods instead of panicking.
- `ReflectWrapper`'s `Call` returns an error for too many arguments or arguments
  of a non-assignable type instead of panicking.
- `ReflectWrapper` and `ReflectDescription` return an error for a nil function
  instead of a reflection panic, and `MustReflectWrapper` panics with that error.
- `ReflectWrapper`'s `Name` returns the function name like `strings.ToUpper`
  and `String` its signature instead of the formatting of a `reflect.Value`.
- `NewJSONArgsFunc` works for functions with a `context.Context` argument,
  passes the caller's context, returns an `ErrParseArgsJSON` for a malformed JSON object,
  and accepts `error` arguments as JSON strings, because it calls `CallWithJSON`.
- `ReflectWrapper` keeps a copy of the passed argument names, and its `ArgNames`
  and the slices of `ReflectDescription` return copies,
  so changing them doesn't rename the arguments of the wrapper.
- `NewStringArgsFunc`, `NewNamedStringArgsFunc` and `NewJSONArgsFunc` no longer panic
  when a results handler returns a non-comparable error such as a slice of errors.
- The printing and logging results handlers like `PrintTo` and `LogTo` no longer replace
  the results with their strings for the results handlers after them.
- The default `TimeFormats` parse `datetime-local` values with seconds like `2026-10-20T14:30:05`.
- `uintptr` is scanned like the other unsigned integers instead of with `fmt.Sscan`,
  with Go integer literal prefixes like `0x10` and a leading `0` for octal as before,
  `""`, `nil` and `null` scan as `0`, and content after the number like `42abc`,
  which `fmt.Sscan` ignored, is an error.
- `httpfun.Handler` and `HandlerNoWrapper` panic again with `http.ErrAbortHandler`,
  so that net/http aborts the response, instead of answering it with 500 Internal Server Error.
- `ScanString` and `TypeStringScanners.ScanString` return an error for non-pointer
  or nil destinations instead of panicking.
- Interface scanners registered with `WithInterfaceTypeScanner` also match types
  that implement the interface with pointer receivers, such as `encoding.TextUnmarshaler`.
- A kind scanner returning `ErrTypeNotSupported` falls back to the default scanner
  like type and interface scanners.
- Scanning `""`, `nil` or `null` into an array sets its zero value instead of failing.
- The documentation states that `encoding.TextUnmarshaler` destinations get the unmodified string
  and `json.Unmarshaler` destinations every input as JSON, so the type validates all input.
- String-valued `json.Unmarshaler` types can be scanned from inputs like `123` or `true`.
- `PrintStructSliceAsTable` leaves out unexported struct fields instead of panicking,
  and returns an error instead of panicking for nil results and slices of non-struct pointers,
  and for structs without exported fields instead of printing a table without columns.
- `LogTo` and `LogWithPrefixTo` log results verbatim instead of treating `%` as format verbs.
- Whole-number float results print as `1` instead of `1.`,
  and `[]byte` results containing whitespace print as text instead of hex.
- `httpfun.Handler` removes the temporary files of uploads that its `RequestArgsFunc` parsed
  after the response, also for requests cloned by middleware, which net/http doesn't clean up,
  and `RequestMultipartFormArgs` removes them when parsing the form fails.
- `httpfun.RespondJSONObject` no longer panics for a nil error result and detects all duplicate keys.
- `httpfun` results writers replace an existing `Content-Type` header instead of adding a second one,
  and `DetectContentType` recognizes JSON arrays.
- `cli.SuperStringArgsDispatcher.PrintCompletion` completes the sub commands of a typed super command
  instead of only matching the first argument, and `DispatchCombinedCommandAndArgs`
  dispatches named sub commands of a super command that also has a default command.
- `cli.StringArgsDispatcher.DispatchCombinedCommandAndArgs` passes the caller's context to the default command,
  `AddDefaultCommand` returns an error instead of replacing an existing default command,
  and shell completion no longer suggests an empty word or prints a trailing space for default commands.
- `gen-func-wrappers` keeps argument descriptions after gofmt reformats `//   name: desc` lines,
  so a second run and `-validate` keep them; Markdown list items like `- name: desc` or `1. name: desc`
  and block comments work too.
- `gen-func-wrappers` generates code that compiles for functions without arguments,
  `CallWrapper` and string-only `CallWithStrings` wrappers, unnamed parameters,
  function-typed parameters with variadic signatures, and signatures with struct tags.
- `function.CallWithJSONWrapperTODO` generates a `CallWithJSON` method
  instead of being silently skipped.
- Generated `CallWithJSON` methods of functions without arguments return an `ErrParseArgsJSON`
  for invalid JSON instead of calling the function.
- Parameter types from packages named unlike their import path (`/v2`, `gopkg.in/yaml.v3`,
  renamed directories) and from aliased or conflicting imports are imported and qualified correctly
  in all generated methods.
- Functions declared per platform are taken from the current platform's file,
  and files are processed in sorted order, so `-validate` results are stable.
- A wrapper type without a var stays a type, and a wrapper var declared after its type
  and methods no longer causes duplicate declarations.
- `-replaceForJSON` imports the replacement type's package and replaces variadic element types,
  and JSON `null` for a replaced argument or variadic element keeps it `nil` instead of passing
  a nil pointer of the replacement type in a non-nil interface, which panicked in the function.
- A `context.Context` argument is detected also when the file imports `context` with another name,
  instead of generating wrappers that pass no context.
- TODO calls in var blocks and with an aliased or dot-imported go-function are rewritten,
  and TODO calls that can't be rewritten are errors instead of being skipped.
- Exported functions of standard library packages can be wrapped,
  and only the imports that wrappers reference are located, so files with cgo's `import "C"`
  or imports for other platforms can be rewritten.
- `gen-func-wrappers` returns an error instead of panicking for an import that can't be located
  and for a named file that is not part of the package build, and its errors name the processed file.
- Wrapping a function whose file dot-imports its parameter types reports a clear error
  instead of generating code that doesn't compile.
- Wrappers needing different packages with the same name in one file, or parameter types
  from packages named like the generator's imports or identifiers, get alternative import names
  instead of producing conflicting or shadowed imports.
- Wrapped functions or imports named like identifiers of the generated code, and declarations
  of the package named like them that the argument types refer to, like `type v int`,
  are reported as errors naming the identifier instead of generating code that doesn't compile.
- Local import prefixes are detected for recursive `dir/...` paths.
- Non-compiling examples in the documentation of all packages and the README are fixed,
  the `CallWithJSONWrapper` documentation states that only a JSON object of named arguments is supported,
  the `gen-func-wrappers` install instructions use `go get -tool` for `go tool gen-func-wrappers`,
  and the documentation states that panics in wrapped functions propagate from the `Call*` methods
  and are only recovered by `httpfun.Handler`.
- The README runs the tests of all modules with `./test-workspace.sh`.
- The help of the `cli` dispatchers no longer lists a `context.Context` argument like `<ctx:context.Context>`,
  which the dispatcher passes, and has no trailing space after commands without arguments.

### Security

- Slice and array literals with more than `MaxSliceLiteralElements` elements are rejected
  with a parse error, answered with 400 Bad Request by `httpfun.Handler`,
  because scanning a 32 MiB literal of a request body allocated about 1.5 GiB.
  `[]any` destinations, like the slice of a `...any` argument, are decoded by `encoding/json`
  without this limit.
- The errors of `ScanString` for integers, floats, booleans, times, durations,
  and slice and array literals quote at most the first 100 bytes of the scanned string
  followed by its length, and strings longer than 256 bytes after trimming whitespace
  are rejected as `time.Time` or `time.Duration` before parsing, because quoting all
  of an invalid 32 MiB request body allocated more than 1 GiB per request.
  The errors of `fmt.Sscan` for other types like complex numbers, and of `encoding/json`
  for struct, map and `[]any` destinations, are unchanged.
- The documentation warns against exposing arguments of types that name files,
  like `fs.File` of go-fs, to untrusted input of `CallWithStrings`, `CallWithNamedStrings`
  or `CallWithJSON`, and the `-replaceForJSON` examples of `gen-func-wrappers`
  no longer use `fs.File`, which would make JSON strings paths of server files.
- An invalid argument value is no longer echoed in error responses,
  and values of the server, like environment variables or data parsed
  by other wrappers, are no longer shown as client errors.

- Update `htmlform` to `go-types` v1.0.0-beta.1 and use its renamed `Validatable` interface for argument validators.
